# MarketLab architecture

MarketLab has two personalities. **Research** helps you understand one asset. The **Lab** helps you test what you think you know. Everything else (Notebook, Replay, and later Portfolio and live monitoring) builds on the same layers.

```
DATA            sources/yahoo.py  sources/sec.py  sources/news.py  sources/peers.py  sources/search.py  sources/logos.py
                marketdata.py   (one door for price bars, with provenance)
                dataquality.py  (every price series is checked before use)
                provenance.py   (value + source + period + reported/estimated)
        ↓
CONDITIONS      conditions.py   (registry of yes/no questions per bar; no look-ahead)
        ↓
EXPERIMENT      experiments.py  (ExperimentDefinition → prepare → detect_triggers → measure_outcomes)
        ↓
STATISTICS      robust.py       (mean/median/CI, trimmed, winsorized, bootstrap, contribution, checks)
                challenge.py    (outliers, time split, recency, parameter neighbours → factual lists)
        ↓
NEWS            tab_news.py     (providers → normalise → dedup → cluster → NewsEvent → rank → store)
        ↓
STORAGE         notebook.py     (definitions + result summaries + challenge, versions, forks)
        ↓
API             marketlab.py    (Flask routes, JSON only)
        ↓
RESEARCH        research_projects.py, concept_library.py (intraday research notebooks, explicit definitions)
        ↓
UI              static/*.js     (draws results; never computes statistics)
```

The rule that keeps this extensible: **the UI never contains strategy logic, and the engine never knows about the UI.** An experiment is data (`ExperimentDefinition`), so it can be saved, re-run, forked, compared across tickers, generated by AI, replayed or monitored without changing the engine.

## ExperimentDefinition (version 2)

```json
{
  "version": 2,
  "instrument": {"symbol": "CAT", "asset_class": "equity"},
  "timeframe": "1d",
  "conditions": [
    {"id": "c1", "type": "price_move", "category": "PRICE",
     "params": {"direction": "falls", "threshold": 5, "window": 5}, "instrument": null, "timeframe": null},
    {"id": "c2", "type": "relative_volume", "category": "VOLUME",
     "params": {"op": "above", "multiple": 1.5, "lookback": 20}}
  ],
  "logic": null,
  "outcome": {"type": "forward_return", "horizon": 10},
  "period": {"start": null, "end": null},
  "benchmark": "SPY",
  "settings": {"overlap": "non_overlapping", "entry": "close", "trim": 0.05}
}
```

- Up to 6 conditions. `logic: null` means AND over all of them. The engine already evaluates an AND/OR tree (`{"op": "or", "args": ["c1", {"op": "and", "args": ["c2", "c3"]}]}`) via `conditions.combine()`; the UI only builds AND for now.
- A condition's `instrument` / `timeframe` are reserved for cross-asset conditions ("SPY above its 200-day average") and intraday conditions.
- Condition types: `price_move`, `relative_volume`, `rsi`, `ma_position`, `ma_cross`, `earnings`. New ones are added with `conditions.register(...)`; the builder, sentence, preview and parameter-neighbour grid pick them up automatically.

### Trigger detection is separate from outcome measurement

```
prepare(definition)        → bars, condition series, combined yes/no series, warm-up, gaps
detect_triggers(prep, H)   → episodes [{index, status}]   (never reads a price after the bar)
measure_outcomes(prep, …)  → forward return, benchmark return, path   (the only forward read)
```

Episodes don't overlap (next start ≥ t + H + 1). Episodes whose window hasn't finished are shown as pending and excluded. Windows that cross a data gap are skipped. A test (`tests/test_quant.py::test_no_look_ahead`) changes every future price and checks that triggers don't move.

**Replay** will use exactly this split: a clock advances `t`, `detect_triggers` runs on bars `[0..t]`, and outcomes are revealed only after `t + H` has been drawn. No separate replay engine.

## Challenge this result

`challenge.challenge(definition)` re-runs the same engine and reports facts, never a score:

- **Outliers:** mean, median, trimmed and winsorized; without the most extreme episode; without top and bottom.
- **Time split:** two halves with equal episode counts, each compared with its own period's normal return. "Held" = same direction and at least a third of the size.
- **Recency:** full history vs last 5 and 3 years (skipped when the sample is identical).
- **Parameter neighbours:** a 3×3 grid over the two main parameters. "Held" = ≥ 75% of cells with n ≥ 10 agree on direction.
- Output: "What survived" and "What should make you cautious", each line with its calculation. Nothing is labelled statistically significant.

## Notebook

Entries store the full definition, the result summary, the challenge findings, notes and a hypothesis. "Update existing" pushes the previous state into `versions` (max 30; notes-only edits don't create a version). "Save as a fork" creates a child with `parent_id`. Duplicate, Open in Lab and Delete are on each card.

## News (multi-source, not Yahoo-dependent)

`sources/news.py` runs every provider in parallel (6 s timeout each), caches each for 15 minutes (failures for 3), and normalises to one article shape. A failing provider is reported in the Sources panel and never blocks the others.

| Provider | Type | Key |
|---|---|---|
| SEC EDGAR 8-K / 6-K | Primary · regulatory | none (`SEC_USER_AGENT`) |
| Company newsroom RSS (auto-discovered) | Company source | none |
| GlobeNewswire | Company press releases | none |
| Federal Register | Primary · government | none |
| FTC and DOJ press releases | Primary · government | none |
| Bing News, Google News (+ policy search), GDELT | News indexes | none |
| Nasdaq, WSJ / MarketWatch / Investing.com feeds, Seeking Alpha | Publications (headline + snippet) | none |
| Yahoo Finance (yfinance + RSS) | Aggregator — one source among many | none |
| Finnhub · Alpha Vantage · Polygon.io | News APIs | optional: `FINNHUB_API_KEY`, `ALPHAVANTAGE_API_KEY`, `POLYGON_API_KEY` |

`tab_news.build_news()` then: keeps articles that name the company → removes duplicate URLs/headlines → groups headlines within 72 h by IDF-weighted similarity into one **NewsEvent** → assigns a category (headline first; SEC item codes for filings) and, for government items, a neutral kind (rule, investigation, award or contract…) → ranks by relevance and materiality, recording the reasons ("why here?") → stores material events in `cache/news_events/<T>.json` (`events_between()` for historical lookup, ready for chart markers and a future `news_event` Lab condition).

MarketLab only reads headlines, snippets and metadata. It links to the original publisher, never fetches article bodies, and never works around paywalls.

## Lab: two workflows

- **Quick test** (`lab.js`, `experiments.py`): one structured sentence on daily bars, tested immediately.
- **Research projects** (`research.js`, `research_projects.py`, `concept_library.py`): notebooks for complex, mostly intraday ideas. URL: `#lab/projects[/<id>]`. Stored as `research/<id>.json`. No AI needed.

A project keeps the **original observation verbatim** (the server refuses to change it; rewordings are added beside it), the terms that still need definitions, explicit **definitions** built from the Concept Library, a **hypothesis** made only from definitions (ordered A→B→C or any order, each with a required state and timing), entry / stop / exit **ideas to compare**, trading assumptions (session, max holding time, contract, costs), open questions, successful / failed / interesting examples, notes, and a **version tree** (`parent_id`, so v3A and v3B can both grow from v2). Projects can be forked (`parent_project_id`).

### Concept Library (`concept_library.py`)

Every concept (FVG, liquidity sweep, swings, equal highs/lows, PDH/PDL, overnight and session levels, VWAP, opening range, displacement, structure break, volume spike, time window, economic event) is data: parameters plus `explain(params)`, which renders the exact rule as sentences. Each states **occurrence**, **confirmation** and **eligibility** times. The FVG has explicit states: CREATED, ACTIVE, ENTERED, PARTIALLY_FILLED, HALF_FILLED, FULLY_FILLED, VALIDATED, INVALIDATED, EXPIRED, each with "known at".

`analyze_observation(text)` is deterministic formalization: it finds instrument, timeframes, concepts (one term per timeframe, so "1H FVG" and "5m FVG" are separate), vague relations ("earlier", "directional", "validates", "fresh") and the rules every test needs (outcome, entry, invalidation, target, session, holding time).

### Intraday data: the best free sources (`intraday/providers.py`, `intraday/composite.py`)

Checked October 2026. **No free, anonymous source of tick or second-level NQ/MNQ data exists** (CME real-time and tick
data need a licensed feed; Dukascopy's tick feed is a Nasdaq-100 *cash-index CFD* with a ~270-point basis, reached through
an undocumented endpoint, so it is not used). Seconds are shown as unavailable and are never built from minute candles.

| Source (no account, no key) | What it gives | Used for |
|---|---|---|
| Yahoo contract series `NQZ26.CME`, `NQH27.CME` … | each quarterly contract while it is listed; 1m ≈ 29 days, 5m ≈ 60 days, 1h ≈ contract life | contract-labelled candles, volume roll rule |
| Yahoo continuous `NQ=F` | front month, Yahoo's own roll, no label; 1h ≈ 2 years | days whose contract has expired (not downloadable any more); verification |
| FirstRate Data public sample | ≈ 2 recent weeks of 1m/5m/1h, unadjusted front month (private use, attribution) | independent cross-check + filling minutes Yahoo lacks |

`AutoProvider` ("auto") assembles one research series per trading day (`composite.assemble`, a pure function):
1. NQ=F candles identical to a contract's candles are that contract (labelled); the rest is "front month (unlabelled)".
2. **Roll rule:** start with the most traded contract; move to a later contract the first day it trades more volume; never back.
   One contract per trading day; unadjusted; every switch is a `CONTRACT ROLL` break that nothing crosses.
3. A missing minute is filled only from a source showing the same contract that day (≥ 90 % identical closes).
4. Two compatible sources that differ (close > 1 pt, high/low > 2 pts) → `SOURCE DISAGREEMENT`, excluded.
5. Provenance per segment (days, contract, source, fills) is shown in the Dataset inspector.

Local cache: every download is merged into `cache/intraday/<source>_<symbol|contract>_<interval>.json`; later downloads
only request what is new (6-hour overlap); `catalog.json` records provider, instrument, contract, resolution, first/last,
download time and quality. Expired contracts are kept once downloaded; a contract Yahoo no longer lists is re-checked once a day.

**Resolution hierarchy.** Higher timeframes are always built from one base series. With base `auto`, a project uses the
coarsest base that divides every timeframe it uses (`dataset.auto_base`): a strategy whose finest step is 5m gets ≈ 60 days
of 5m data instead of ≈ 29 days of 1m. Execution on 1m forces a 1m base.

### Intraday engine (`intraday/`)

```
bars.py        normalized bar {timestamp (bar open, UTC s), OHLCV, symbol, interval, provider, contract};
               Series with per-bar flags (suspect, partial, after_gap), contracts and sources
sessions.py    America/New_York trading day (18:00 → 17:00), windows, quarterly expiries, contract codes
quality.py     missing, duplicate, out-of-order, explicit CONTRACT ROLL, heuristic roll artifact (unlabelled data only),
               abnormal gap, stale, SOURCE DISAGREEMENT; NQ↔MNQ cross-check (same contract month only)
engine.py      resample (clock-aligned; 4h from 18:00; 1d per trading day); a bar is visible only at open + interval;
               regime(): nothing crosses a roll
dataset.py     build() + status (LIVE / DELAYED / LATEST AVAILABLE / HISTORICAL) + inspector + auto_base
detectors.py   FVG (+ states), PDH/PDL, overnight high/low, swings, equal highs/lows, sweeps
concepts.py    displacement, market structure (BOS / CHoCH / MSS), candle shapes, directional move, volume expansion,
               volatility expansion, previous-week high/low, opening range (+ breakouts), session VWAP (+ crosses)
strategy.py    facts → ordered conditions (context conditions only need to hold at the setup) → setups with
               "why this matched" → setup funnel → simulate every entry × stop × exit → metrics → replay;
               why_not(t) explains a non-match condition by condition; luck() places a real trade in the distribution
```

Every detector reports `occurred_at` and `confirmed_at` (a candle close). Swings exist only after their right-hand candles
close; structure breaks only use swings confirmed before the breaking candle opened; sweeps are confirmed at the reclaim
close; FVGs exist at candle 3's close. Suspect candles never create or confirm anything. Tests cut the data at time T and
check that nothing known at T changes.

## Describe My Trade (`formalize.py`, `static/describe.js`)

Two workflows produce the **same** project structure (definitions, conditions with roles, entries, stops, exits, settings,
timeframe roles) and run the **same** engine: *Quick formalize* (describe the trade) and *Manual* (define everything).

`formalize.parse(text, answers, personal)` is deterministic: concept mentions (with timeframe, direction, phrase) →
definitions from the Concept Library or the user's saved definitions → ordered conditions (context / prerequisite /
setup / confirmation; "first", "after X" respected) → entry / stop / target / time rules → recipe + timeline →
**ambiguities** (only choices that change detection or results; each has options and a "common reading") →
**unsupported** concepts (order block, SMT, Fibonacci, news…: never dropped silently; nearest measurable version only
if chosen) → status. READY only when nothing is open. Nothing is added that the description doesn't contain.

Projects keep `trade_description.original` forever (later wordings are revisions); `formalization` stores the parse,
answers and the rules fingerprint it produced, so hand edits show as *diverged* and a re-parse first saves the current
rules as a version. Saved definitions live in `research/personal_definitions.json` (one automatic per concept).
Variations (`make_variation`) save the current rules as a version, apply one change and save the result as a child
version; `/compare` runs versions side by side (no winner declared). Project status: IDEA → DEFINING → READY → TESTED →
REFINING. Optional AI (`/ai`) rewords or explains; it never calculates.

Routes: `POST /api/research/projects/<id>/{describe,answer,reparse,mode,actual-trade,variation,duplicate,why-not,compare,ai}`,
`GET /api/research/projects/<id>/dataset`, `POST /api/research/parse` (preview), `GET/POST /api/research/personal-definitions`,
plus the earlier `/run` and `/replay`.

## Simplified Lab: describe → understand → test (v9)

Lab tabs: **Describe an idea** (default; Trade or Invest) · Logged trades · Quick test · Research projects
(the full editor, = "Advanced setup") · Saved experiments (Notebook). Every idea is an ordinary Research
Project (`kind: idea | trade_check`), so Advanced simply opens it in the full editor.

- **Interpretation** (`formalize.parse`, `static/idea.js`): each ambiguity has a severity (`SEVERITY`).
  LOW / MEDIUM are auto-resolved with the best default (`auto: true`) and listed under "Defaults used" /
  "Assumptions used"; only HIGH ones (direction, stop, target, which liquidity pools) are asked. The
  result is one compact card (`card`: headline + Context / Prerequisites / Confirmation / Entry / Stop /
  Exit / Session). Back-references ("after the sweep", "CE of the FVG") are not new conditions.
  Concepts without a detector are kept as `unsupported` conditions, never dropped.
- **Core vs secondary**: context, the first sweep and the final trigger are core; the rest secondary.
- **Match ladder** (`intraday/ladder.py`): EXACT · VERY SIMILAR (required fixes + the single secondary
  relaxation that keeps the most *setups* — never chosen by returns) · BROADER (every secondary
  relaxation). Each tier lists original → relaxed; core rules are never relaxed; tiers are never mixed;
  every variant counted is added to the project's search log. `diagnose()` separates DATA (missing/short
  history, peer market missing) from CONCEPT (no detector) from PATTERN (never occurred).
- **SMT** (`concepts.smt`, concept `smt_divergence`): consecutive confirmed swings of this market vs the
  comparison market's extreme over the same candles ± `max_lag_bars`; divergence needs ≥ `min_ticks` in
  both; known only when the swing is confirmed and the lag window has closed. Peers: ES, NQ, YM.
- **Session ranges**: Asia 20:00–00:00, London 02:00–05:00, NY AM 09:30–12:00 high/low
  (`session_range_levels`), known at the window end.
- **Scale-out exits**: `scale_out` (fraction at first R target, rest to R or liquidity pools).
- **Logged trades**: `research_projects.parse_trade_text` / `log_trade`; the realized R is placed in the
  distribution of comparable setups (`strategy.luck`), worded as "This realized outcome was unusually
  strong / weak / within the usual range relative to comparable historical setups".
- **Results**: key numbers + distribution first; combinations, funnel, breakdowns and outlier sensitivity
  under "Advanced statistics".

## Investment Lab (`invest.py`, `static/invest.js`)

Thesis text + horizon (3m · 6m · 12m · 24m · 5y · custom) + basket (stocks/ETFs, weights, cash).
Per holding: Yahoo info, daily prices, reported fundamentals (`tab_risk._fundamental`) and dependencies
quoted from the latest annual report (`risk_intel.exposures`). Hidden exposure map = factors shared by
holdings, with strength (disclosed / emphasized / measured / classification / mentioned). Boilerplate
macro/policy topics are listed separately and never count as concentration. Price correlation and
dependency overlap (Jaccard of material factors) are shown side by side; pairs are classified
same bet / hidden overlap / moves together / independent — correlation alone is never called a
dependency. Stress test ("what must be true" / "what could break it") and scenarios trace exposure
pathways only; no return forecasts. Theme candidates are research candidates, not recommendations.

## v13: Invest performance and workflow

**Ticker resolution (`resolver.py`).** Prose never becomes holdings by regex. Holdings come only from company
names/aliases ("Nvidia" → NVDA), `$TICK`, and ALL-CAPS listed tickers that aren't ordinary words. Word-like or
single-letter tickers (AI, IT, ON, ALL, F…) become a question ("Did you mean Ford (F)?") only with context, else
they are listed as "not treated as tickers". `invest.parse_thesis` returns `detected / suggestions / ignored`.

**Backend stages.** `basic(ticker)` (Yahoo info + daily bars, 30-min cache) and `profile(ticker)` (filings, fund
look-through, factors, 6 h cache) both go through `_single_flight`, so concurrent requests for one ticker share
one fetch. `POST /api/invest/quick` (names, sectors, 1Y correlation; seconds) runs before `POST /api/invest/analyze`
(filings; dependencies, themes, macro, map). Unresolvable tickers are dropped with "Could not resolve X" and the
rest renormalised. `refresh: true` clears the caches for those tickers.

**Frontend (`static/invest.js`).** Several *analyses* (name, tags, notes, text, holdings with weight drafts,
horizon, cash) autosaved to `localStorage["marketlab.invest.v1"]` — inputs only, never results. Results live in
memory per analysis. The page is three regions (`#inv-top`, `#inv-compose`, `#inv-out`); typing never re-renders:
parsing (debounced, stale-guarded) updates only the detected row and chips, weights update only the total. Each
Analyze carries a run id + AbortController; a response is painted only if it still belongs to the active analysis.
Tabs render one at a time and are memoised by (result stamp, tab UI state). Debug overlay: `?debug` or
`localStorage["marketlab.debug"]="1"`.

**v14 input reliability.** Editable fields keep local drafts and never trigger analysis (the "What if…" box
keeps a per-analysis draft in `INV.whatIf`; only Trace/Enter commits). When a stage lands, `paintStage()` updates
progress, summary and the active tab in place instead of rebuilding the results, and opening Advanced fills only its
own body. Each Invest tab keeps its own DOM pane (`#inv-panes > [data-pane]`): revisiting a tab only un-hides it; a
pane is rebuilt only when its data stamp or its own UI state changes. Traced scenarios are cached per analysis
result; recent scenarios (5) are saved with the analysis inputs. `/api/invest/scenario` accepts the analysis inputs
and rebuilds an expired analysis (e.g. after a server restart). Map hover work runs only when the hovered node
changes; SVG drop-shadows and per-edge transitions were removed. The global Replay key handler ignores text fields.
Browser regression test: `tests/browser/invest_ui.e2e.js` (optional; Node + Playwright).

## Risk intelligence (`risk_intel.py`, `static/tab_risk_intel.js`)

`GET /api/stock/<T>/risk/intel` reads SEC filings only (10-K Business / Risk Factors / Legal Proceedings and 8-K items + exhibits, cached in `cache/sec_docs/`) and returns four sections, each with `state` = ok / no_evidence / not_run / error:

- **Dependencies & exposures**: named suppliers, manufacturers, customers, competitors, geographies, macro and policy topics. Each item carries its quote and filing; percentages appear only when the filing states them (`disclosed`), otherwise `qualitative`.
- **Government & policy**: entity, action, date, status, connection, source. Neutral wording, no judgement of officials.
- **Controversies & material events**: categories plus a status taxonomy (alleged, under investigation, lawsuit filed, settled, dismissed, resolved…). Allegations are never shown as findings.
- **Guidance history**: raised / lowered / reiterated / initiated / withdrawn / mixed, previous vs new, and the reported actual from SEC XBRL revenue.

Extraction is pattern-based (gazetteer + relationship phrases), never generated from model knowledge.

## Data quality

`dataquality.check_daily(bars, splits)` classifies every daily return above 40%:

- **Unadjusted split:** the jump matches a recorded split within ±4 days → earlier prices are rescaled (LIKELY ERROR, corrected).
- **Bad print:** the price snaps back within 12% the next day → that day is removed (LIKELY ERROR, removed).
- **Possible split:** the jump matches a whole-number ratio but no split is recorded → WARNING, kept.
- **Otherwise:** a real move → INFO, **kept**.

It also checks invalid prices, data gaps, stale quotes, volume spikes and OHLC consistency. Results are shown in the Lab ("Data checks") and summarised in the Risk tab.

## Research data sources

- **Prices, quotes, estimates, short interest, analyst targets:** Yahoo Finance via yfinance. Delayed, and no key needed.
- **Official identity, filings, reported financials, quarterly revenue, share counts:** SEC EDGAR. Free, and needs `SEC_USER_AGENT`.
- **News:** the multi-source layer described above.
- **Peers for "Test elsewhere":** Yahoo similar-symbol recommendations and industry top companies, plus sector SPDR ETFs and SPY/QQQ.
- **Company search:** Yahoo search, with the SEC company list as the fallback.
- **Logos:** Financial Modeling Prep's public logo images, cached on disk, with an initials fallback.
- **Charts:** TradingView Lightweight Charts (Apache-2.0), bundled in `static/vendor/`.

Guidance, named suppliers/customers/competitors, government actions and controversies now come from filing text (see Risk intelligence). Still unavailable: revenue by segment and geography as structured data, and historical revenue estimates.
